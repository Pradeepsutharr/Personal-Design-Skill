# Landing Page UX Standards

## Purpose

Landing pages should communicate value quickly, establish trust, create desire, and guide users toward a clear action. Premium visual design must support conversion rather than distract from it.

## Core Principle

A visitor should understand the product, audience, value, and next step within seconds.

Do not begin by choosing decorative sections. Begin with the user's questions:

1. What is this?
2. Is it for me?
3. Why should I care?
4. Can I trust it?
5. What should I do next?

## Hero Section

The hero is the highest-priority area.

It should usually contain:

- Clear primary headline
- Concise supporting value proposition
- Primary CTA
- Optional secondary CTA
- Relevant visual proof or product visualization

The headline should communicate the outcome, not merely the technology.

## Hero Headline

Strong headlines are:

- Specific
- Benefit-oriented
- Easy to understand
- Short enough to scan
- Relevant to the target audience

Avoid vague claims such as `The future of everything` unless the brand context makes the meaning immediately clear.

## Hero Visual

The visual should reinforce the product story.

Good choices include:

- Product UI
- Interactive mockup
- Relevant workflow visualization
- Data visualization
- Carefully designed abstract visual

Avoid generic stock imagery that does not explain the product.

## Primary CTA

The primary CTA should be obvious.

Use action-oriented copy:

- `Start free`
- `Book a demo`
- `Get started`
- `See the platform`

Avoid competing primary CTAs with equal visual weight.

## Trust Signals

Trust can be established through:

- Customer logos
- Metrics
- Testimonials
- Case studies
- Security/compliance information
- Product screenshots
- Recognized integrations
- Awards or certifications when legitimate

Only use claims supported by real information.

## Social Proof

Testimonials should communicate specific outcomes when possible.

Prefer:

- Who the customer is
- Their role/company context when permission exists
- What problem they solved
- A measurable or concrete result

Avoid anonymous generic praise when stronger proof is available.

## Feature Sections

Do not simply list features.

Translate features into user outcomes.

Structure can be:

**Problem → Capability → Outcome → Proof**

Each section should have a clear purpose.

## Product Screenshots

Screenshots should be readable and intentional.

- Show meaningful UI.
- Highlight important interactions.
- Avoid tiny unreadable screenshots.
- Use realistic data where possible.
- Keep visual treatment consistent.

## Section Rhythm

Create visual rhythm by alternating:

- Content-heavy sections
- Visual sections
- Proof sections
- Conversion sections

Avoid making every section identical.

## Visual Hierarchy

Each section should have:

- One clear primary message
- Supporting content
- One logical action where appropriate

Avoid multiple competing headlines and CTAs.

## Navigation

Navigation should support discovery without overwhelming the visitor.

- Keep key destinations visible.
- Make the primary CTA easy to find.
- Use dropdowns only when they improve discoverability.
- Keep mobile navigation simple.

## Conversion Design

Place conversion opportunities at natural decision points.

Common locations:

- Hero
- After key value proposition
- After social proof
- After product capabilities
- Final CTA

Do not add a CTA after every paragraph.

## Pricing

If pricing is public, make it easy to compare.

Clearly communicate:

- Plan differences
- Important limits
- Billing frequency
- Included capabilities
- Primary recommended option

Avoid dark patterns or hiding critical pricing information.

## FAQ

Use FAQs to resolve real objections.

Good FAQ topics include:

- Pricing
- Security
- Setup
- Integrations
- Migration
- Support
- Compatibility

Do not use FAQs solely to add keyword-rich text.

## Footer

A premium footer should be useful and organized.

Consider:

- Product links
- Solutions
- Resources
- Company
- Legal
- Contact
- Social links

Avoid giant link walls.

## Responsive Design

The mobile landing page should be intentionally designed.

Check:

- Hero composition
- CTA width and placement
- Navigation
- Screenshot scaling
- Section spacing
- Typography
- Card stacking
- Horizontal overflow

## Performance

Marketing pages should still be fast.

- Optimize hero images.
- Avoid excessive video.
- Lazy-load below-the-fold media.
- Avoid shipping large client-side libraries for decorative effects.
- Keep animations lightweight.
- Use server-rendered content where appropriate.

## SEO

Landing pages should include:

- Unique title
- Useful meta description
- Semantic headings
- Crawlable content
- Descriptive internal links
- Optimized images
- Appropriate structured data when relevant
- Canonical URL strategy

Do not sacrifice readability for keywords.

## Accessibility

Ensure:

- Semantic headings
- Keyboard-accessible navigation
- Visible focus states
- Sufficient contrast
- Descriptive link text
- Meaningful alt text
- Accessible CTAs
- Reduced-motion support

## Premium Visual Direction

A premium landing page should feel intentional rather than overloaded.

Use:

- Strong typography
- Generous but purposeful whitespace
- Refined product visuals
- Restrained color palette
- Subtle depth
- Consistent radius and spacing
- High-quality motion

Avoid:

- Excessive gradients
- Random floating shapes
- Stock imagery without purpose
- Huge text with little information
- Too many cards
- Excessive animation

## Landing Page Review

Before shipping, ask:

- Is the value proposition immediately clear?
- Is the hero visually premium?
- Is the primary CTA obvious?
- Does the visual explain the product?
- Is trust established early enough?
- Are features translated into outcomes?
- Is the page easy to scan?
- Is spacing consistent?
- Can typography be improved?
- Is the mobile experience excellent?
- Is the page SEO-friendly?
- Is accessibility handled?
- Will Lighthouse score well?
- Is the code reusable and performance-friendly?
- Is this something I'd be proud to ship?
